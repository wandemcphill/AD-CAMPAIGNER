# Supabase Authorization Matrix

Generated from `packages/database/prisma/schema.prisma` on 2026-08-03. This matrix intentionally treats the Nest API and workers as the trusted policy enforcement layer for private data. Supabase PostgREST exposure is limited to public catalog/listing reads only.

## Architectural Decision

The repository does not use Supabase Auth or direct Supabase clients for application data access. Authentication and authorization are implemented in the Nest API with custom JWT/session tables and guards. Prisma is the database access layer for the API and worker. Therefore, private tables should not be queried directly from browser/mobile clients through Supabase REST.

Required operational invariant: the backend `DATABASE_URL` must use a Supabase service-role/postgres/BYPASSRLS-capable connection. These migrations enable RLS but do not use `FORCE ROW LEVEL SECURITY`, specifically so the backend service connection can continue to operate. If the backend is changed to a non-bypass database role, private-table queries will fail and the role should be fixed rather than weakening policies.
